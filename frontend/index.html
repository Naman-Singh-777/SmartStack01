What happens to a question

  1. Route. A small trained classifier labels the question simple, moderate or complex and picks a model size.
  2. Cache. If a very similar question was answered in the last hour, the saved answer is returned at no cost.
  3. Retrieve. The best few passages from the knowledge base are found. Weak matches are dropped to save tokens.
  4. Answer. The chosen model writes the reply. Without an API key the server quotes the documents instead.
  5. Plan. A planner suggests which cloud, region and machine type to run the work on.

What to keep in mind

  • The classifier learned from 120 hand-written questions. It is a good start, not a finished product.
  • Prices and machine costs are example numbers. Edit them in backend/app/config.py and scheduler.py.
  • The compute planner only recommends. It does not start machines.
  • Without a language model key the server answers from its own documents. Adding a key turns on live answers.

How it works

Five small steps, each in its own file. Open the file next to its card to read the code.

  2. 2Cache
  3. 3Retrieve

1. Route

backend/app/classifier.py

TF-IDF turns the words of a question into numbers. Four extra numbers describe its shape: length, how many things it asks for, commas and code. Logistic regression learns from 120 labelled examples which numbers mean simple, moderate or complex.

Loading accuracy from the API.

Why it saves money: the cheapest model that fits answers the question. If the classifier is unsure, the question moves up one tier.

2. Cache

backend/app/cache.py

Two checks must both pass before an answer is reused: the questions share most of their letter patterns, and most of their important words. The second check is why the capital of France and the capital of Spain do not share an answer.

Why it saves money: a repeated question costs nothing and returns in milliseconds.

3. Retrieve

backend/app/retriever.py

Documents are cut into chunks. Each chunk is scored by exact word match and by fuzzy letter match, and the two scores are mixed 60 to 40. Only chunks above a minimum score are sent on.

Why it saves money: fewer input tokens, and the model reads less noise.

4. Answer

backend/app/llm.py

With ANTHROPIC_API_KEY set, the model chosen in step 1 writes the reply and real token counts are used for the cost. Without a key, the server quotes the best matching sentences and estimates tokens.

Why it saves money: the large model is the exception, not the default.

5. Plan

backend/app/scheduler.py

Picks the GPU class from the tier, then the cheapest region. Interactive work stays under an 80 ms latency budget on on-demand machines. Batch work uses cheaper spot machines in any region.

Why it saves money: the right size of machine in the right place.

Run it yourself

README.md

cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload

# in another terminal
cd frontend
python -m http.server 8080

Then open http://localhost:8080. Run pytest in backend to check everything.
